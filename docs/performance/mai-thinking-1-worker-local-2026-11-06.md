# MAI-Thinking-1 后台绘制与文字层优化（2026-11-06）

> 更正：测试中的一次位置跳动来自用户手动操作，之前将其判断为双栏竞态没有成立依据。由此增加的滚动目标匹配逻辑及对应测试已撤回，恢复原有滚动来源识别。下文三轮对照及其源码哈希是撤回前的历史记录，不能当作当前代码的复测结果。撤回后验证另记于文末。

在本机可见的 Electron 生产构建中，用用户指出的 PDF 副本完成三轮交替对照、三轮快速滚动和真实阅读器交互检查。基线为 `dc0089c`，已包含前一轮页面虚拟化、渲染队列、文字分批及高亮样式缓存。

## 修改

- PDF.js 与原生 canvas 在持久后台线程中绘制，前台只解码、显示页面图像。保留两个解析后的文档，PNG 内存缓存最多 64 项 / 64 MiB；文件被替换后缓存自动失效。任务可取消，单张画布最多 16 MP，后台不可用时回退到原有浏览器绘制。
- 每个阅读栏使用一个共享的 ShadowRoot 隔离文字样式。密集的水平 LTR 文字使用小块 SVG 原生文字，保留全部字符串、顺序和 PDF 坐标；普通文字、RTL、竖排和 marked content 继续使用 PDF.js 文字层。
- 文字布局与位图使用独立队列。滚动时让出未完成的文字布局，停止后恢复；已有选区的自动滚动仍能补全文字。完成的文字层继续保留。
- 选区和撤销状态由当前阅读栏提供，处理独立复现的撤销按钮状态问题。

译文第 7 页有 27,355 个文字片段，第 9 页有 568,947 条绘图指令。优化针对显示过程；两份源 PDF 与测试副本的 SHA-256 在测试后仍一致。显示缓存只在内存中存在。

## 本机结果（撤回前历史数据）

Intel Core i7-9750H、16 GB RAM、Retina DPR 2，Electron 44.9.3 / Chromium 152。1220 × 780 可见且有焦点的窗口，双栏从第 7 页开始，向下滚动 1800 CSS px 再返回，速度 360 px/s；两个版本交替各三轮。开始计时前等待当前页位图和文字完成，再静置 800 ms。

平均间隔减少约 66%，P95 减少约 85%，主线程任务耗时减少约 68%。三轮均返回原始位置，最大滚动位置与指定距离一致；已记录两个栏的逐帧位置。

速度提高到 **1800 px/s** 后另测三轮：平均间隔中位数 **18.5 ms**，P95 **33.3 ms**，长任务均为 **0**，缺失画布采样 **0 / 125**，均返回起点并达到指定距离。

这是主线程 `requestAnimationFrame` 回调响应指标，不是显示器最终呈现帧率。普通滚动仍有一次 **82.5 ms** 的峰值，快速滚动最差 **83.2 ms**，不能声称任何情况下都完全无卡顿。空白检查是每 100 ms 的离散采样，跳过页间空隙和部分译文以外的页面。计时不含首次打开等待；尚未覆盖后台翻译并发负载及其他操作系统。

## 功能与验证（撤回前记录）

- 在真实 Chromium 窗口中验证普通文字和 SVG 文字的字符范围、跨 SVG 分块选区，以及选区进入阅读器控件。
- 在密集译文中完成高亮、撤销、重做、放大、缩小和搜索；搜索高亮范围实际落在 SVG 文字上。自动测试选择应用生成的本机菜单项，不调用新增调试接口。
- 57 项相关测试通过，覆盖后台位图、缓存失效、取消、原始像素/旋转/纸张色、密集文字完整性、延迟滚动事件、双栏选区、虚拟化、历史高亮及缩放。
- 类型检查和生产构建通过。全量测试初跑 393 项通过、11 项失败、27 项跳过；其中端口/超时相关的 5 项失败在单独复测时通过，相关三个文件共 34 项全通过。剩余 6 项需要本地缺失的 BabelDOC ONNX 模型或目标字体。之后新增的三个回归测试已包含在上述 57 项中。

测量与交互测试使用临时文库，已安装的应用没有被替换。当前项目构建包含优化，重新用项目版本启动后生效。
