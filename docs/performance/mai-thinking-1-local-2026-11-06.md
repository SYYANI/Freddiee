# MAI-Thinking-1 本机专项优化（2026-11-06）

针对用户指出的 **MAI-Thinking-1: Building a Hill-Climbing Machine**，用真实文件副本在本机可见的 Electron 窗口中复现、修改并做了三轮交替对比。此次基线是本轮修改前的工作区，已经包含上一轮页面虚拟化和渲染队列优化；不是未优化的旧版本。

## 文档和瓶颈

- 原文 109 页，BabelDOC 译文 10 页；复现用户的双栏阅读位置，从第 7 页（索引 6）开始。
- 译文第 7 页有 27,355 个文字片段，原文对应页为 282 个；译文第 9 页有 568,947 条绘制指令，原文对应页为 3,506 条。这些密集页放大了样式重算和绘制开销。
- Chromium 时间线确认存在长时间样式重算。历史高亮即使没有任何范围，也会在页面完成、滚动窗口变化时删除并重新插入 `::highlight` 样式表，导致整个文档的样式反复失效。

## 保留的修改

1. 历史高亮规则在文档生命周期内复用，重绑范围时只更新范围和事件，不重建样式表。空历史和空搜索不创建规则或空 Highlight 注册项。
2. 文字层在离屏容器中按 128 个片段分批生成，批次之间让出事件循环，完成后一次挂载；保留原始片段顺序、字体、语言和 marked-content 边界。
3. 两个阅读栏共享位图队列，另用一个文字布局队列。耗时的文字测量不再占住位图队列，让另一个阅读栏等待空白。

没有修改 PDF 字节、译文、批注存储、同步格式或 renderer 权限。

## 三轮实测

环境：Intel Core i7-9750H、16 GB RAM、MacBookPro15,1、Retina DPR 2；Electron 44.9.3 / Chromium 152。窗口为 1220 × 780，处于可见、有焦点状态。每轮重新加载，等待当前页画布和文字就绪后，从第 7 页向下滚动 1800 CSS px 再返回，速度 360 px/s；两个版本交替各运行三轮。

以下耗时取各轮指标的中位数：

| 指标 | 本轮修改前 | 修改后 |
| --- | ---: | ---: |
| 平均帧回调间隔 | 153.3 ms | 58.5 ms |
| P95 帧回调间隔 | 665.6 ms | 135.3 ms |
| 每轮最大帧回调间隔 | 1983.8 ms | 882.3 ms |
| 主线程 TaskDuration / 每次往返 | 11,489 ms | 8,422 ms |
| Long task 总耗时 / 每次往返 | 9,711 ms | 4,998 ms |
| Long task 数 / 每次往返 | 20 | 54 |
| 视口中心未完成画布采样（合计） | 119 / 245 | 0 / 533 |

P95 帧回调间隔降低约 **80%**，平均间隔降低约 **62%**，主线程任务耗时降低约 **27%**。长任务的累计时间减少约一半，但次数增加，不能将其描述为所有长任务指标都改善。

空白检测每 100 ms 检查两个栏的视口中心所在页面是否已有完成的画布，跳过页间空隙。主线程阻塞也会延迟检测，因此它是离散采样，不是空白持续时长比例。修改后的三轮都没有采到缺失画布；还等待文字层完成后检查了双栏截图，原文、译文和表格正常显示。

这是主线程 `requestAnimationFrame` 的响应指标，不是显示器的最终呈现帧率。仍存在约 0.9 秒的单轮最大帧间隔，密集图表首次处理依然会卡顿，不能声称已经稳定 60 FPS。未覆盖缩放、手写或后台翻译并发负载。测试使用临时文库，没有替换已安装的应用。

逐轮结果、机器信息、源码/构建哈希及 PDF 哈希保存在 [实测 JSON](./mai-thinking-1-local-2026-11-06.json)。原始帧序列、基线源码快照和截图保存在本次测试输出的临时目录 `freddie-pdf-bench-kvsoLF`。源文库的两份 PDF 与测试副本的 SHA-256 在测试后仍相同。
